# 网易 MCPK 格式说明与解包 / 封包工具

**作者：nmbb** · **版本：1.1.1** · **Windows 10 / 11 x64**

这个项目提供一个中文图形工具，用来提取网易《我的世界》客户端的 MCPK 资源封包，并将修改过的已有文件重新封回原有结构。仓库同时说明当前实现使用的字段、校验方法、运行步骤和支持范围。

**[下载 Windows EXE](downloads/nmbb_MCPK解包封包工具.exe?raw=true)** · [下载校验信息](downloads/SHA256SUMS.txt) · [验证记录](docs/VALIDATION.json)

EXE 内置运行所需组件，双击即可打开，不需要在使用者电脑上安装 Python。也可以直接运行仓库中的 Python 源码。

> 目前提供的是“原结构回封”：修改已有文件内容，保留文件数量、名称、目录和 `contents.json`。新增、删除、改名或从普通目录创建全新 MCPK，均不在本版本支持范围内。

## MCPK 是什么

部分网易客户端将资源存放在 `data/resource_packs` 下的单个二进制文件中。这类文件可以没有扩展名；识别时应读取文件内容，不能仅看名字。

本工具识别的容器以四个 ASCII 字节 `MCPK` 开头。当前已验证样本的资源数据由多个独立 zlib 流构成，文件路径记录在内部 `contents.json` 中。索引则负责将文件名键值、相对偏移、压缩大小和原始大小关联起来。

`MCPK` 文件头只表示格式标记。是否能成功提取，仍要看实际数据流能否解压、文件清单是否完整，以及索引和文件名键值能否全部匹配。

它和国际版常见的 `.mcpack` 不是同一容器格式。把 MCPK 改名为 `.zip` 或 `.mcpack`，不会把它转换成 ZIP。

## 下载与运行

1. 点击页面上方的 **下载 Windows EXE**。
2. 将程序保存到你可以写入文件的目录。
3. 双击 `nmbb_MCPK解包封包工具.exe`。
4. 根据需要选择“解包”或“封包”页签。

程序默认以普通用户权限运行，不会自动替换游戏目录中的文件。每次都需要明确选择输入和一个新的输出位置。

### 校验下载文件

同目录的 `downloads/SHA256SUMS.txt` 记录已发布 EXE 的 SHA-256。可在 PowerShell 中计算下载文件的值，再与清单比较：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath '.\nmbb_MCPK解包封包工具.exe'
```

下载目录中的 EXE 对应本仓库发布时的代码快照。修改源码后，应自行重新编译，而不能把下载目录中的旧 EXE 当作修改后的版本。

## 图形界面解包

1. 打开“解包”页签，选择源 MCPK 文件。
2. 指定一个**尚不存在**的输出目录，例如 `D:\MCPK\trial_解包`。
3. 点击“开始解包”，等待进度达到 100%。
4. 使用“打开输出位置”查看资源，使用“打开报告”查看文件数量和校验记录。

对于没有扩展名的原包，直接选择文件即可，不需要重命名。若输入不是支持的 MCPK，或数据不完整，程序会显示错误并停止。

解包时会额外保存一份原包。处理大资源包前，应为**全部解压文件 + 原包副本 + 临时处理空间**预留磁盘容量；不能只按源文件大小估算。

## 修改文件并回封

1. 先用**本工具**解包，得到资源文件和 `.mcpk_tool` 元数据目录。
2. 修改已有的图片、模型、JSON 或其他资源内容，保持原文件名和相对路径。
3. 保留 `contents.json` 原字节，保留整个 `.mcpk_tool`。
4. 打开“封包”页签，选择刚才的完整解包目录。
5. 指定解包目录之外、尚不存在的输出文件，例如 `D:\MCPK\trial_回封.mcpk`。
6. 点击“开始封包”，等待自动回读校验完成。

如果没有修改任何文件，输出应与原包逐字节一致。如果修改了内容，工具会检查输出内每个文件的 SHA-256 是否与选定目录中的内容一致。

输出名中的 `.mcpk` 仅便于辨识。工具不会把结果自动部署进游戏，也不会自动改动输入原包。

### 资源内容本身由谁校验

回封检查负责确认“选定的字节被正确写回容器”。它不判断模型结构、JSON 字段、贴图尺寸或其他资源语义是否适用于目标客户端。因此，容器回读成功后，仍需在目标客户端中验证实际加载及效果。

## 解包目录与元数据

一个简化的项目目录如下：

```text
trial_解包/
├─ contents.json
├─ manifest.json
├─ netease_config.json
├─ textures/
│  └─ ...
└─ .mcpk_tool/
   ├─ original.mcpk
   ├─ project.json
   └─ unpack_report.json
```

| 文件 | 用途 | 是否应手动修改 |
| --- | --- | --- |
| 原始资源文件 | 实际可编辑的资源内容 | 可以，保持路径和名称 |
| `contents.json` | 原包内部文件清单 | 本版本要求完全不改 |
| `.mcpk_tool/original.mcpk` | 回封模板及原始压缩流来源 | 不要修改 |
| `.mcpk_tool/project.json` | 工具版本、源包哈希等项目记录 | 不要修改 |
| `.mcpk_tool/unpack_report.json` | 提取文件及 SHA-256 记录 | 供查看 |

之前通过其他方式提取的普通目录，如果没有这些元数据，需要重新从原包执行一次本工具解包。只补一个空的 `.mcpk_tool` 目录不能替代有效模板。

## 命令行调用

图形界面和命令行调用使用同一套后端逻辑。无参数启动时显示窗口；带子命令时执行任务，并将运行结果写入 `--result` 指定的 UTF-8 JSON 文件。

```powershell
# 解包
& '.\nmbb_MCPK解包封包工具.exe' unpack `
  'D:\MCPK\vanilla_trial' `
  'D:\MCPK\trial_解包' `
  --result 'D:\MCPK\unpack_result.json'

# 回封
& '.\nmbb_MCPK解包封包工具.exe' repack `
  'D:\MCPK\trial_解包' `
  'D:\MCPK\trial_回封.mcpk' `
  --result 'D:\MCPK\repack_result.json'
```

EXE 不附带控制台窗口，处理结果应读取 JSON 文件。成功时 `ok` 为 `true`，进程退出码为 0；失败时 `ok` 为 `false`，退出码为 1，并记录错误信息。自动化脚本需要等待进程退出后再读取结果。

从 Python 调用时可以明确等待：

```python
import subprocess

subprocess.run([
    r'.\nmbb_MCPK解包封包工具.exe',
    'unpack', r'D:\MCPK\vanilla_trial', r'D:\MCPK\trial_解包',
    '--result', r'D:\MCPK\unpack_result.json',
], check=True)
```

回封另会生成 `输出文件名.report.json`，其中记录修改文件数、输入及输出哈希、容器验证状态，以及 `game_runtime_verified: false`。

## 容器结构与解析规则

当前实现将支持的 MCPK 分为以下几部分。具体条目数量和 `contents.json` 的流位置由数据决定，不使用固定文件数。

```text
文件起始                                   文件结束
┌────────────┬────────────────┬─────────────────────┬────────────┐
│ 文件头     │ 索引 / 目录数据 │ 连续的 zlib 文件流   │ 129 字节尾部│
└────────────┴────────────────┴─────────────────────┴────────────┘
                               ↑
                         文件头给出的 doff
```

### 文件头

| 绝对位置 | 数据 | 本工具的处理 |
| --- | --- | --- |
| `0x00` 起 4 字节 | `MCPK` 标记 | 必须匹配 |
| `0x14` 起 4 字节 | 数据区起点 `doff`，小端整数 | 检查是否在文件内及支持范围内 |
| 其他头部字段 | 当前工具无需重建的内容 | 回封时保留原字节 |

### 文件流与文件清单

工具从 `doff` 顺序解压 zlib 成员，记录每个流的起点、压缩大小、解压大小和 SHA-256。实际解压会检查 zlib 流是否完整及校验是否通过。

随后定位 JSON 文件清单候选，并要求路径数量加清单文件自身恰好等于文件流数量。`contents.json` 会插回它实际所在的流位置，再对全部路径和索引做匹配。

因此，本实现不假定清单总是第 0 个或第 3 个流。格式不明确、清单不完整或出现多个无法消歧的候选时，会报错，避免猜测文件名后继续写盘。

### 统一的文件记录窗口

本工具在已验证样本中查找下列连续窗口。这里的 `k` 是**文件名键值的起点**，不是固定的全局条目边界：

| 相对 `k` 的位置 | 长度 | 含义 |
| --- | --- | --- |
| `+0` | 4 字节 | 文件 basename 的 32 位键值，小端 |
| `+4` | 4 字节 | 相对 `doff` 的流偏移，小端 |
| `+8` | 3 字节 | 压缩大小，小端 |
| `+11` | 1 字节 | 保留字节 |
| `+12` | 3 字节 | 解压大小，小端 |

工具要求键值、偏移、压缩大小和解压大小全部匹配。不同包的索引起点和对齐可以不同，所以实现按实际匹配定位字段，不把某个样本的条目基址套到所有包。

`name_hash.py` 提供文件名键值的兼容算术实现：按 UTF-8 编码，仅取最后一个 `/` 后的文件名，再执行对应的 32 位状态运算。目录名不直接加入这一文件键值输入。

### 实现上限

| 项目 | 当前边界 |
| --- | --- |
| 单个解压流 | 256 MiB 安全上限 |
| 清单候选 JSON | 64 MiB |
| 头部与索引区域 | 64 MiB |
| 文件流数量 | 250,000 |
| 回封文件的原始大小 | 必须小于 `2^24` 字节，即小于 16 MiB |
| 回封文件的压缩大小 | 必须小于 `2^24` 字节 |
| 流相对偏移 | 必须能写入 32 位无符号字段 |
| 尾部 | 本版本要求正好 129 字节，并原样保留 |

解包的流大小保护与回封字段上限不是同一限制。某个输入能被读取，不代表超出 24 位大小范围的编辑文件能够回封。

## 回封过程与完整性检查

1. 读取 `.mcpk_tool` 中的原包副本，确认其 SHA-256 与项目记录一致。
2. 重新解析模板，恢复实际文件集合及字段位置。
3. 对比目录中的文件集合，拒绝新增、缺失或改名。
4. 对每个文件计算 SHA-256，判断内容是否有变化。
5. 未修改时保留原压缩数据；已修改时重新压缩并记录新大小。
6. 按原流顺序输出数据，更新所有相关流偏移与大小字段。
7. 保留原头部中未使用字段、目录结构数据及原始尾部。
8. 回读临时输出，对比文件名、索引、内容哈希及未修改压缩字节。
9. 校验通过后，保存为新的目标文件，并写出报告。

解包也先写入新的临时目录，完成后再改为目标目录。工具对路径穿越、绝对路径、盘符、Windows 设备名、大小写重复、文件与目录冲突，以及回封输入中的符号链接和目录联接执行拒绝处理。

本次 EXE 直接更新现有封装中的署名常量和 Windows 版本资源，没有重新编译应用功能代码。原有 Python 指令字节保持不变；封装检查记录见 [PATCH_INFO.json](docs/PATCH_INFO.json)。

详细结果见 [验证记录](docs/VALIDATION.json)。记录对应 1.1.1 构建及 2026-10-20 的实际验证：40 项本地原包回归、12 项合成容器测试、7 项 EXE 验证均通过。文件名键值实现另通过 2,056 组结果对比。

本地样本验证覆盖 `vanilla_trial`、`chemistry`、`chemistry_1.20.50` 等包的提取、原样回封、修改后再次提取，以及损坏输入和不支持操作的拒绝。样本属于本机验证输入，未上传到仓库。

**容器结构与字节回读验证，不能替代网易客户端实际加载和游戏效果验证。**

最后 129 字节的具体用途尚未确认。本工具保留其原始内容，不据此断言修改后的包一定会被所有客户端版本接受。当前没有把修改回封后的游戏加载标记为已验证。

## 常见问题

### 文件没有扩展名，怎么选？

文件选择器默认“所有文件”，直接选择 `vanilla_trial` 等文件即可。程序按文件头识别。

### 为什么不能直接选择普通文件夹封包？

工具需要原包的头部、目录结构、保留字段、压缩流和尾部作为模板。普通文件夹不包含这些信息，因此需要先解包原文件。

### 已经解包过，为什么还提示缺少元数据？

其他解包器输出的目录，或只提取了资源文件的目录，不等于本工具项目。需要重新解包一次，并保留 `.mcpk_tool`。

### 为什么不能修改 `contents.json`？

当前版本保留原始文件集合及索引结构。清单改变可能涉及路径、排序和结构字段的同步重建；本工具不对这类改动作支持承诺。

### 为什么输出位置必须在项目目录外？

避免上一次生成的封包或报告被当作下一次需要打包的新资源文件。请选择项目之外的新路径。

### 改了 JSON，回封成功却在游戏里无效？

检查资源本身是否适用于目标版本、实际加载的是哪个资源层，以及同名资源是否被覆盖。回封成功只确认对应文件字节完整写入了输出容器。

### 程序占用很多磁盘空间？

解包目录同时保存解压文件和完整原包副本，处理过程中还会使用临时输出。完成后可按自己的备份需求管理项目，但删除原包副本后将失去回封模板。

### 能处理所有网易版本吗？

不能这样保证。格式、字段和客户端行为可能变化；程序会对能验证的布局继续处理，对无法验证的布局报错。
